## Verified Results

### Core

- `test_hash_utils.py`: 12 unit tests passed and one Linux integration test was skipped.
- NTLM known vectors passed:
  - `password`
  - `Password`
  - empty password
- A SHA-512-crypt hash generated by Passlib was generated and verified.
- Yescrypt is now supported through the maintained `yescrypt` package and was
  verified with a real generated yescrypt hash, a matching password, and a
  mismatching password.
- The installed Unix backend was initialized successfully as `passlib`.

### PySide6

PySide6 6.12.0 opened successfully in an offscreen Qt smoke test. The new GUI
contains four tabs:

1. Password Analyzer
2. System Account Auditor
3. Password Generator
4. Reports and History

The legacy Tkinter implementation is retained at
`passguard/gui_tkinter_legacy.py` but is not imported by the application.

### Wordlist Benchmarks

The benchmarks streamed entries from temporary files without loading the complete
wordlist into memory.

| Entries | Execution time | Peak traced memory | Process CPU time |
|---:|---:|---:|---:|
| 100,000 | 0.181 s | 0.151 MiB | 0.172 s |
| 1,000,000 | 1.775 s | 0.151 MiB | 1.750 s |
| 5,000,000 | 9.213 s | 0.151 MiB | 8.969 s |

These values measure wordlist streaming, not salted Linux verification or Windows
NTLM account extraction.

### Cryptographic Benchmarks

Measured on Windows 10 with Python 3.15.1:

| Benchmark | Candidates | Matches | Time | Peak traced memory | CPU time |
|---|---:|---:|---:|---:|---:|
| NTLM candidate hashing | 100,000 | 1 unique hash | 5.528 s | 0.264 MiB | 5.531 s |
| yescrypt verification | 1 | 1 | 40.077 s | Not recorded | Not recorded |
| SHA-512-crypt with 1,000 rounds | 3 | 1 | 57.256 s | 0.010 MiB | 56.828 s |

These values are representative of the currently installed Windows Python
backends. They are not Linux end-to-end audit benchmarks. The Linux procedure
must be rerun on Ubuntu for native libcrypt timing and real account auditing.

### Linux

Linux integration testing was skipped because the available environment is
Windows. The platform-gated test is in
`tests/integration/test_linux_shadow_audit.py`.

No real `/etc/shadow` weak-account or strong-account validation is claimed.
The exact Ubuntu procedure is in
`docs/linux_ubuntu_validation.md` and `scripts/ubuntu_linux_audit_test.sh`.

### Windows

Synthetic NTLM file matching passed independently for known NTLM vectors.
Live SAM extraction was not executed because the available environment is
Windows 10 and the process was not running with administrator privileges.

The custom parser remains a legacy RC4/DES implementation. Modern SAM revisions
and AES handling are not claimed. Live SAM remains `NOT SUPPORTED` until a real
Windows hive and disposable test accounts are available for validation.
The exact validation procedure is in `docs/windows_sam_validation.md`.

## Modified and Added Files

- Modified Unix hash backend and capability checks.
- Added UID, salt, rounds, verification backend, and audit source fields.
- Added PySide6 GUI and retained the legacy Tkinter module separately.
- Added unit, integration-gated, redaction, and benchmark tests.
- Split core, GUI, and development dependencies.
- Added unique temporary hive directories with `finally` cleanup.

## Known Limitations

- No Linux root integration test was run in this environment.
- No live Windows SAM hive was acquired or parsed.
- No Windows weak/strong test-account validation was run.
- Yescrypt support depends on the `yescrypt` package and must be re-tested after
  dependency changes.
- Modern Windows SAM format support is not claimed.
